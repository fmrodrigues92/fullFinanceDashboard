## Achados

### [SEC-01] `faturamentoPorCompetencias` sem ownership check interno · BAIXO

**Arquivo:** `app/src/Invoicing/Infrastructure/Persistence/EloquentInvoiceRepository.php` linha 123

**Problema:** o método filtra invoices apenas por `company_id`, sem verificar que a empresa pertence ao usuário autenticado. A segurança atual depende 100% do caller (`DashboardController` → `ListCompaniesUseCase($userId)`) ter pre-validado os company IDs. Se um segundo entry point invocar `GetFaturamentoDashboardUseCase` com um `companyId` arbitrário, haverá leitura cross-tenant.

**Contexto (por que é BAIXO e não ALTO):** não há segundo entry point hoje; o único caller é o `DashboardController` que garante ownership via `ListCompaniesUseCase`. O padrão é consistente com os outros métodos do repositório (`listForCompany`, `findForCompany`), que também são company-scoped sem user_id direto.

**Correção recomendada:** adicionar `$userId` como parâmetro e fazer JOIN com `companies` para verificar ownership dentro da query, ou adicionar um guard no use case:

```php
// Opção A — join no repository (preferível)
->join('companies', 'invoices.company_id', '=', 'companies.id')
->where('companies.user_id', $userId)
->where('invoices.company_id', $companyId)

// Opção B — guard no use case (mais simples)
// GetFaturamentoDashboardUseCase recebe CompanyRepository, verifica ownership antes de chamar o InvoiceRepository
```

### [PERF-01] N+1 queries no DashboardController · BAIXO

**Arquivo:** `app/Http/Controllers/DashboardController.php` linhas 40–42

**Problema:** o loop `foreach ($companies as $company)` emite uma query SQL por empresa (`faturamentoPorCompetencias`). Com N empresas: 1 query de companies + N queries de faturamento.

```php
foreach ($companies as $company) {
    // 1 query por iteração
    $faturamentoPorEmpresa[(string) $company['id']] = $getFaturamento($company['id'], $competencias);
}
```

**Contexto (por que é BAIXO e não MÉDIO):** cada query é eficiente (GROUP BY com índice em `[company_id, data_emissao]`) e o número de empresas por usuário é pequeno por natureza do produto (finanças pessoais). Com 5 empresas: 6 queries totais, < 10 ms em Postgres local.

**Correção recomendada (quando escalar):** adicionar método `faturamentoPorCompetenciasMultiEmpresa(array $companyIds, array $competencias)` que faz uma única query com `whereIn('company_id', $companyIds)` e agrupa também por `company_id`:

```php
->selectRaw("company_id, TO_CHAR(data_emissao, 'YYYY-MM') as competencia, tipo, SUM(valor_brl::numeric) as total, COUNT(*) as quantidade")
->whereIn('company_id', $companyIds)
->where('is_simulation', false)
->whereNull('deleted_at')
->groupByRaw("company_id, TO_CHAR(data_emissao, 'YYYY-MM'), tipo")
```

### [PERF-01] `app/Http/Controllers/DashboardController.php:40-42` — consolidar N queries em 1

Adicionar método `faturamentoPorCompetenciasMultiEmpresa` ao repository para uma única query com `whereIn`:

```php
// Interface (InvoiceRepository.php) — novo método:
/**
 * @param  int[]    $companyIds
 * @param  string[] $competencias 'YYYY-MM'
 * @return array<int, array<string, array{total: float, notas_emitidas: int, itens: list<array{tipo: string, valor: float, quantidade: int}>}>>
 */
public function faturamentoPorCompetenciasMultiEmpresa(int $userId, array $companyIds, array $competencias): array;

// Implementação (EloquentInvoiceRepository.php):
public function faturamentoPorCompetenciasMultiEmpresa(int $userId, array $companyIds, array $competencias): array
{
    // inicializar resultado com zeros para todos companyId × competencia
    $result = [];
    foreach ($companyIds as $cid) {
        foreach ($competencias as $comp) {
            $result[$cid][$comp] = ['total' => 0.0, 'notas_emitidas' => 0, 'itens' => []];
        }
    }

    if (empty($companyIds) || empty($competencias)) {
        return $result;
    }

    $minDate = min($competencias) . '-01';
    $maxDate = (new DateTimeImmutable(max($competencias) . '-01'))
        ->modify('first day of next month')
        ->format('Y-m-d');

    $rows = InvoiceModel::query()
        ->join('companies', 'invoices.company_id', '=', 'companies.id')
        ->selectRaw("invoices.company_id, TO_CHAR(invoices.data_emissao, 'YYYY-MM') as competencia, invoices.tipo, SUM(invoices.valor_brl::numeric) as total, COUNT(*) as quantidade")
        ->whereIn('invoices.company_id', $companyIds)
        ->where('companies.user_id', $userId)
        ->where('invoices.is_simulation', false)
        ->whereNull('invoices.deleted_at')
        ->where('invoices.data_emissao', '>=', $minDate)
        ->where('invoices.data_emissao', '<', $maxDate)
        ->groupByRaw("invoices.company_id, TO_CHAR(invoices.data_emissao, 'YYYY-MM'), invoices.tipo")
        ->get();

    foreach ($rows as $row) {
        $cid  = (int) $row->company_id;
        $comp = $row->competencia;
        if (! isset($result[$cid][$comp])) {
            continue;
        }
        $valor = (float) $row->total;
        $qtd   = (int) $row->quantidade;
        $result[$cid][$comp]['total']          += $valor;
        $result[$cid][$comp]['notas_emitidas'] += $qtd;
        $result[$cid][$comp]['itens'][]         = [
            'tipo'       => $row->tipo,
            'valor'      => $valor,
            'quantidade' => $qtd,
        ];
    }

    return $result;
}

// DashboardController.php — substituir loop por chamada única:
$companyIds = array_column($companies, 'id');
$faturamentoPorEmpresa = $getFaturamento($userId, $companyIds, $competencias);
// (GetFaturamentoDashboardUseCase e sua interface precisam ser atualizados para a nova assinatura)
```

**Nota:** ao aplicar PERF-01, o SEC-01 também fica resolvido (o join com `companies.user_id` entra na mesma query), tornando desnecessário manter o método `faturamentoPorCompetencias` (single-company). O `/backend` pode consolidar as duas correções em um único PR.
